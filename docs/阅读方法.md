## 1. 四层结构

魂 3 里一个敌人由四部分构成：一具身体、一张行为图、一套动画、以及一个"脑子"。只有最后一个是 AI，
而且它和前面三样都不在同一个文件里。

| # | 层 | 位置 | 负责什么 |
|---|---|---|---|
| 1 | 参数 | `Data0.bdt` → `NpcParam`、`NpcThinkParam`、`BehaviorParam`、`AtkParam_Npc`、`Bullet` | 数值与**指针**。`NpcThinkParam.battleGoalId` 指向战斗脚本，`logicId` 指向非战斗脚本；另外还有视野/听觉距离、`nearDist`/`midDist`/`farDist`、`BattleStartDist`、回撤距离等 |
| 2 | **AI 脚本** | `script/aicommon.luabnd.dcx`、`script/mXX_XX_XX_XX.luabnd.dcx` | **决策本体**。编译过的 Lua 5.0 字节码：权重表、随机掷点、连段编排、反应触发 |
| 3 | 行为 / 动画 | `chr/cXXXX.behbnd.dcx`（Havok 行为图）、`chr/cXXXX.anibnd.dcx` → `*.tae` | 播出脚本点名的动作；动画事件（`InvokeAttackBehavior`、无敌帧、取消窗口）挂在这里 |
| 4 | 判定 / 伤害 | `BehaviorParam` → `AtkParam_Npc`、`Bullet` | 打中之后发生什么 |

两个实用推论：

* **行为图不是大脑，是动画状态机。** 改它改变的是"这一招怎么播、怎么混合"，不是"什么时候选它"。
* **chr 包号由 npc id 推出**：`chr/cXXXX`，其中 `XXXX = NpcParam id / 100`。米狄尔 `621100` →
  `chr/c6211.*`，他的 `.tae`（也就是招式号）就在这里。

所有 AI 包共用同一套命名，看文件名就知道是哪一类：

| 文件 | 作用 |
|---|---|
| `<id>_battle.lua` | 战斗 AI（`battleGoalId` 指向的就是它） |
| `<id>_logic.lua` | 非战斗 AI：巡逻、待机、对话 |
| `<id>_platoon.lua` | 队伍 / 队形协同 |
| `common_*.lua`、`goal_list.lua` | 公共函数库与 goal 常量表 |

`*_logic.lua` 基本是空壳：读出参数里的 `battleGoalID`，然后当作顶层 goal 挂上去。真正有意思的行为
全在 `*_battle.lua`。

## 2. 决策函数

### 2.1 每次要行动时，现填一张权重表

战斗 goal 的 `Goal.Activate` 会在 AI 需要决定下一手时被调用。它构造一张 `w[招式] = 权重` 表，
分支条件就是这套 AI 的全部"思考"——血量比例、跑的是哪个 think 参数变体、玩家身上的 SpEffect 状态、
玩家的角度、以及距离分档：

```lua
if ai:GetHpRate(TARGET_SELF) <= 0.55 and ... then      w[50] = 100   -- 跨过阶段线
elseif ai:IsInsideTarget(TARGET_ENE_0, AI_DIR_TYPE_B, 150) then
                                                       w[6] = 70; w[20] = 30
elseif InsideRange(ai, goal, 105, 60, -1, 3) then      w[4] = 55; w[5] = 45
elseif dist >= 10 then                                 w[1] = 75; w[2] = 25
else                                                   w[3] = 20; w[7] = 25; w[9] = 25
end
if ai:HasSpecialEffectAttribute(TARGET_ENE_0, SP_EFFECT_TYPE_TARGET_DOWN) then
    w[21] = w[21] + 300                                -- 你躺在地上：追击
end
```

（灰烬审判者古达，`aicommon/Gunda_battle.lua`，节选。）

权重是整数、不做归一化，只看比例。分支是互斥的——第一个命中的条件生效，所以 `if` 链的**顺序本身
就是优先级**。

### 2.2 冷却的实现方式是"把权重压小"

```lua
function SetCoolTime(ai, goal, attack_id, cooldown_seconds, weight, floor_value)
    if weight <= 0 then return 0
    elseif ai:GetAttackPassedTime(attack_id) <= cooldown_seconds then return floor_value
    end
    return weight
end
```

调用形如 `w[1] = SetCoolTime(ai, goal, 3000, 10, w[1], 1)`：3000 这一手用完之后 10 秒内被压制。
注意最后一个参数——所谓"冷却"通常是**降到 1，而不是 0**，也就是"概率很低"而不是"不可能"。也有 boss
传 `0`，那才是真的封掉。

### 2.3 掷点

```lua
local total = 0
for i = 1, 99 do total = total + weights[i] end
local roll = ai:GetRandam_Int(1, total)      -- 1..total，含端点
local acc = 0
for i = 1, 99 do
    acc = acc + weights[i]
    if roll <= acc then act = acts[i](); break end
end
```

（`aicommon/common_battle_func.lua`，`Common_Battle_Activate`，压缩过。）

所以每一手的流程是：按状态分支 → 按冷却缩放 → 累加权重掷一次 → 跑选中的那个 `ActNN` 函数。挂着调试
菜单时，`DbgGetForceActIdx()` 可以完全绕过掷点、强制指定第 N 手——测试单招时很有用。

### 2.4 一个 Act 是一串连段，不是单次挥击

`ActNN` 函数内部还有一次独立掷点，用来选连段变体，然后用带距离限制的子目标把各段排好：

```lua
local r = ai:GetRandam_Int(1, 100)
if r <= 30 then
    goal:AddSubGoal(GOAL_COMMON_ComboTunable_SuccessAngle180, 10, 3000, TARGET_ENE_0, 8.5)
    goal:AddSubGoal(GOAL_COMMON_ComboRepeat, 10, 3001, TARGET_ENE_0, 4.5)
    goal:AddSubGoal(GOAL_COMMON_ComboFinal, 10, 3026, TARGET_ENE_0, 5.2)
elseif r <= 60 then ...
```

`ComboAttackTunableSpin` / `ComboTunable_SuccessAngle180` 永远是第一段（先转身面向你再出手），中间是
`ComboRepeat`，最后是 `ComboFinal`。每段都带最大距离：你退得够远，剩下的段就跳过——这就是"连段会
提前结束"的原因。

### 2.5 打断层

`Goal.Interrupt` 可以在动作进行中放弃当前计划、插进别的东西。触发条件是引擎固定的一组：

| 触发 | 什么时候 |
|---|---|
| `INTERUPT_Damaged` | 它受到伤害 |
| `INTERUPT_UseItem` | **你使用了道具**（元素瓶——"喝药必被打"就是这段代码） |
| `INTERUPT_Shoot` | 你射击 / 施法 |
| `INTERUPT_ActivateSpecialEffect` | 它正在观察的某个自身 SpEffect 被激活（用来做连段取消） |
| `INTERUPT_TargetOutOfAngle` / `INTERUPT_TargetOutOfRange` / `INTERUPT_FindAttack` | 目标移出观察扇形 / 距离，或观察中的攻击开始 |
| `INTERUPT_Inside_ObserveArea` | 目标进入观察中的地图区域 |

处理方式通常是 `goal:ClearSubGoal()` 之后插一手反击，有时外面再套一层随机。所谓"AI 读指令"的
真实版本就是这样：它不读手柄，它只对引擎发布的**状态变化**做反应。

### 2.6 阶段与换形态

Boss 的"二阶段"不是脚本里随时间变化的标志位，而是 `SpEffect` 判断之后整段分派到**另一份脚本**。
薪王化身的整套武器形态切换只有十几行：

```lua
Goal.Activate = function (ai, goal)
    if ai:HasSpecialEffectId(TARGET_SELF, 5408) then      goal:AddSubGoal(GOAL_LastBoss_Gwyn_Battle, -1)
    elseif ai:HasSpecialEffectId(TARGET_SELF, 5407) then  goal:AddSubGoal(GOAL_LastBoss_Magician_Battle, -1)
    elseif ai:HasSpecialEffectId(TARGET_SELF, 5405) then  goal:AddSubGoal(GOAL_LastBoss_CurvedBlade_Battle, -1)
    elseif ai:HasSpecialEffectId(TARGET_SELF, 5404) then  goal:AddSubGoal(GOAL_LastBoss_PiercingSword_Battle, -1)
    else                                                  goal:AddSubGoal(GOAL_LastBoss_LargeSword_Battle, -1)
    end
end
```

上面每个 goal 对应 `aicommon/LastBoss_*_battle.lua` 里一张独立的权重表。这些 SpEffect 是战斗的事件脚本
（`event/*.emevd`）加的，不是 AI 加的。所以想改"阶段什么时候开始"，该动的是事件脚本，不是 AI 脚本。

第二种模式：脚本可以干脆跳出权重表。米狄尔在半血时就是这样（挂上一手之后直接 `return true`），
用来保证某段演出无论 RNG 如何都只发生一次。

## 3. 那些数字是什么

AI 脚本里的 `3000`、`3029`、`3014`…… 是**动画号**，不是参数行号。依据：

* `BehaviorParam`（NPC 表）里 `behaviorJudgeId` 最大只到 999，而脚本用的号远超这个范围，并且与角色
  `anibnd` 内的 `a00X_00NNNN.hkx` 动画文件名一一对应。
* Souls Modding Wiki 的 API 说明直接把这个参数命名为 `AnimationID`。

伤害链是分开的、且更靠后：

```
AI 脚本选中动画 3029
   └─ chr/cXXXX.anibnd.dcx 里的动画 3029（*.tae）
        └─ TAE 事件 "InvokeAttackBehavior"，BehaviourJudgeID = N
             └─ BehaviorParam 行（variationId 来自 NpcParam.behaviorVariationId，judgeId = N）
                  └─ AtkParam_Npc / Bullet → 判定盒、伤害、削韧、击退
```

三个推论：改伤害完全不碰 AI；改一手的**节奏**要改 TAE 而不是脚本；想知道某个号是哪一招，只能去看。

## 4. 四步读一个 boss

1. **找到文件。** 在 `data/boss_index.tsv` 里搜名字，取 `battle_lua` 列。（`think_id` 是
   `NpcThinkParam` 行号；`(Heatup)`、`(Orb)`、`(Spirit Clone)` 这类变体可能共用一个脚本，也可能指向
   兄弟脚本。）
2. **读 `Goal.Activate`。** 那就是完整的优先级链：哪种状态打开哪个分支、每个分支里每一手多少权重。
   紧接其后的 `SetCoolTime` 行给出每一手的冷却。
3. **读 `ActNN`。** 每个函数就是一手（或一套编排好的连段）。第一个 `AddSubGoal` 给出动画号，后面的行
   给出后续段和它们的距离上限。
4. **把号变成名字。** 在 **DS Anim Studio** 里打开角色（载入 `chr/cXXXX.anibnd.dcx`，
   `XXXX = npc id / 100`），看 TAE 动画列表，把 3000–3039 逐个播一遍；或者看录像按段数、攻击距离、
   冷却去对号。

额外但很有用：wiki 的 Lua AI 函数手册记录了反编译代码看不出来的语义——比如 `GetDist` 是从角色**原点**
算起、并按角色 hitRadius 做了偏移，所以你贴进它身体里时这个值是负的；`IsInsideTarget` 的角度是给定
方向两侧的半宽。

## 5. 想解本仓库没带的脚本（可选）

本仓库只带了 26 场 boss 用到的 67 个脚本。要解别的敌人、或者把全部 29 个包都解出来，用随包的
`tools/decompile_all.py`（约 1100 个文件、20 分钟）：

```
python tools/decompile_all.py --game "<你的游戏>/Game" --witchy <WitchyBND.exe> \
    --decompiler tools/DSLuaDecompiler/DSLuaDecompiler.dll --out dump
```

只解单个文件用 `tools/decompile.cmd <字节码.lua> -o <输出.lua>`。
前提：你自己的游戏已用 UXM 解包，且从官网下了 WitchyBND。

## 7. 已知局限

* **覆盖率 87%。** 749 行里 653 行能追到专属战斗脚本，其余没有。
* **反编译不是逐字节完美重建。** 读控制流和常量足够，但偶尔会有函数被还原成空分支（米狄尔攻击后的
  间距 goal 就是一例）。任何反常结论都请回字节码或游戏里验证之后再拿去论证。
* **脚本不管节奏。** 帧数据在 TAE（`*.anibnd.dcx`）和 `AtkParam_Npc` 里；AI 只决定**哪一手**。
* **事件脚本是另一套系统。** 场地脚本、阶段触发、血条名字、生成点都在 `event/*.emevd`；AI 对它们造成的
  结果（SpEffect、旗标）做反应，但并不包含它们。
